# Fuel Trip Planner

Open **Map → Plan a fuel trip** for a combustion, mild hybrid or full hybrid vehicle. A plug-in hybrid can plan in fuel-only mode. Select the fuel grade, enter the usable tank capacity, and check the starting level, reserve, consumption estimate and detour limit before routing. The start defaults to the vehicle's position, then to the phone's position when available. You can use up to three vias, make a round trip and pick a departure time for the stop ETAs. The map has an independent **Fuel stations** layer, a compact vehicle panel and a manual refresh. The fuel source and licence are listed in **Settings** with the other data sources.

## Data and updates

Source is the **Ministero delle Imprese e del Made in Italy — Osservaprezzi Carburanti**, [Carburanti – Prezzi praticati e anagrafica degli impianti](https://www.mimit.gov.it/it/open-data/elenco-dataset/carburanti-prezzi-praticati-e-anagrafica-degli-impianti), reused and transformed for display and routing under the [Italian Open Data License 2.0](https://www.dati.gov.it/content/italian-open-data-license-v20). The app fetches the [station registry](https://www.mimit.gov.it/images/exportCSV/anagrafica_impianti_attivi.csv) and the [daily 08:00 price export](https://www.mimit.gov.it/images/exportCSV/prezzo_alle_8.csv) directly. The 08:00 timestamp describes the snapshot. The date at the top of the file and a price's individual communication date can differ.

The importer validates headers by name and joins by `idImpianto`. The archived 29 July 2026 exports use a date preamble and pipe delimiters. The station file is UTF-8 and the prices file contains ASCII text. The importer also handles semicolon, comma and tab headers, UTF BOMs and Windows-1252 as a decoding fallback. It resolves duplicate records, filters invalid coordinates and anomalous quotes, and keeps the most recently communicated offer for each standard grade and service. Regular petrol, diesel and LPG are in EUR/L. Compressed methane (CNG) is in EUR/kg. LNG, HVO and proprietary premium grades are outside the standard-grade list. A quote older than seven days, without a timestamp or dated in the future is excluded from the cheapest highlight. Where compatibility is known, missing quotes remain usable and leave the cost unquoted.

The first visit to the fuel map schedules network-constrained WorkManager refreshes every 12 hours. The foreground refresh checks the daily window at 08:30 in Europe/Rome and accepts the previous day's snapshot. Android can defer background work. A manual refresh can bypass the daily check. Automatic retries have a 15-minute in-process cooldown. The cache is a private gzip file written to a temporary file, synced and atomically replaced after validation. Errors, older exports and substantial registry or price truncation preserve the last good snapshot. A spatial grid indexes stations for corridor queries. The map converts the selected grade and service to GeoJSON off the UI thread and uses native MapLibre clustering through zoom 11. Price labels from zoom 12 and numeric cluster counts below zoom 12 use independent sources, keeping markers and clusters available when style glyphs are unavailable. A verified plan clears the catalogue layers and shows the route, waypoints and selected stops. Closing the plan restores the catalogue. Each source and layer is restored independently after a style reload or a partial initialization. A fuel map left at its default location uses an Italy overview until the first position arrives. The green marker denotes the lowest decile of fresh prices in the selected catalog and filter. The detail card shows quote age and the map shows last successful synchronization.

The existing charger pipeline builds weekly global static tiles from Geofabrik and publishes them with GitHub Actions. Fuel prices change daily and both Italian exports are small enough for on-demand downloads. Direct ingestion keeps the data source authoritative and allows forks and local builds to use the feature independently of a publishing workflow.

## Vehicle inputs and consumption

The form marks departure, destination, tank capacity and starting fuel as required. Intermediate stops and trip settings are optional. The planner fills in the last Stellantis fuel percentage when available. For petrol and diesel, it can estimate the starting quantity from the reported range and baseline rate if the percentage is missing. The user can override either value and use a percentage or enter a quantity.

The vehicle API's fuel readings give level and range. LionFlow can also fill in the tank capacity when the vehicle metadata identifies a documented model. The Peugeot 208 Hybrid 100 e-DCS6 uses 44 L for petrol. Other models currently use manual entry. Manual tank capacity and consumption are saved by vehicle and fuel grade. Hybrid profiles account for the electric contribution through observed fuel rates. [Peugeot technical specifications](https://www.peugeot.fr/content/dam/peugeot/france/b2c/documentation/catalogues/2412/CT_Nouvelle_208_applicable_au_02_janvier_2025.pdf)

The planner builds its prediction after routing. It uses verified local GPS traces on the same road first, then comparable trips, then a robust estimate from all valid history. Without enough supported observations it uses the typical profile. The model compares average driving speed, distance and duration, plus the share of fast segments and nearby endpoints when available. A geographically matched trace must agree at nine points on the route. An average speed difference over 28 km/h rules out a comparable trip. A 150 km motorway trip can inform a much longer motorway journey while short urban trips tend to contribute to the car-wide fallback. A weighted median and robust outlier limits reduce the influence of unusual samples. History-based rates avoid a second generic speed adjustment. A manual rate remains available.

The displayed average, consumed litres and value use expected consumption. The optimizer uses a separate prudent curve and minimum tank reserve. A newly configured vehicle defaults to a 5% margin and existing saved preferences are retained. The proposed purchase amounts and remaining fuel are from the prudent scenario. Fuel consumed on ferry segments is zero. Debug builds provide a local leave-one-out backtest with MAE, MAPE and bias by distance band. See the review report for unit handling, data availability and the benchmark. [Review report](FUEL_PLANNER_REVIEW.md)

## Routing and optimization

`FuelPlanner` reuses LionFlow's Photon search, OSRM servers, `Place`, `RouteData`, MapLibre and navigation patterns. A round trip routes through the waypoints and turnaround. `FuelCorridor` projects compatible stations onto short road blocks and retains separate directional passes. The geographic search radius follows the configured detour limit, with a practical range of 0.6 to 12 km. The geographic offset helps rank candidates. Only the road route determines the added distance.

The automatic check prioritizes nearby stations within the starting range and publishes a feasible plan as soon as it finds one. It then checks another mixed group, with a total budget of 16 station routing requests. A trip that can be completed on its starting fuel skips the corridor and station requests. **Check more stations** checks up to eight candidates and makes up to 14 network requests per press. It keeps the verified stations and confirmed constraints, takes fresh candidates from the full corridor and reserves a slot for an eligible retry. The shortlist weighs quoted price, estimated purchasable fuel, remaining range, freshness, likely detour and coverage along the route. It can keep searching in later groups even when a group yields no better plan. The three strategies are compared over the accumulated road-verified stations and retain their prior plans when a new result fails to improve the strategy score or reduce detour fuel at the same score.

Station routing responses are cached in memory for 24 hours, and itinerary geometry for six hours. The planner reuses the geometry when fuel inputs change and uses the already calculated comparison when switching strategy. Fuel requests start at least 1.1 seconds apart. A 429 stops the current batch and pauses Fuel Planner requests for at least 60 seconds or the longer delay supplied by the router. Temporary failures can be retried. [Routing policy](https://routing.openstreetmap.de/about.html)

For stations away from the route, OSRM first tries a directional exit upstream and a downstream re-entry with the station as an intermediate waypoint. It can try a wider interval and a return to the projected point. Near-route stations try the loop first. The entry and exit use the original direction and tight snap tolerances, and windows respect user waypoints and ferry boundaries. The model subtracts the distance, time and fuel of the replaced road and checks the extra kilometres against the user limit. The solver checks both access legs against the reserve and prevents two stops from replacing an overlapping section. A snapped waypoint within the public road graph is subject to the quality of that graph and the finite set of tested windows.

Debug diagnostics show corridor, shortlist and verified quote statistics, remaining candidates, itinerary and station request counts, cache hits and per-candidate verification outcomes. The extension status reports new checks, retries, accepted candidates and whether the group improved a plan. [Incremental search technical report](FUEL_INCREMENTAL_SEARCH.md)

The optimizer searches ordered stops with exact fuel balances and Pareto dominance on fuel and score. A greater fuel level with lower or equal score can dominate an arrival on an unedited plan. Edited trips disable that dominance because the lock or a fixed amount may interact with tank headroom. A size guard retains low-cost and high-fuel states when edited trips produce very large frontiers. Candidate and purchase-size limits still make this a bounded search. A valid edit updates all strategies. Station alternatives are tested against reserve, capacity and other locks before showing differences in total time and pump spending.

- **Economy** minimizes estimated fuel purchases. Stale and missing quotes use an uncertainty allowance in scoring.
- **Balanced** uses the same estimate plus EUR 0.40 per minute added by detouring and refuelling.
- **Fast** minimizes total travel time, including detours and refuelling.

The planner subtracts the fuel saved on the replaced road from the fuel burned on both access legs. The net amount changes the required purchase volume and breaks ties between plans with the same strategy score. The trip summary and stop cards report expected net detour fuel separately from pump spending. The displayed value uses the station quote or the route reference when the quote is missing. Pump spending already includes fuel bought to cover the detour. The strategy comparison and replacement dialog also show the amount needed for detours. Identical stops and quantities appear as the same solution. Switching strategies reuses the same route and verified candidates.

Fuel Planner labels use English source strings and LionFlow’s existing translation table for French, German, Spanish, Norwegian Bokmål and Italian.

Refuelling time is 5 minutes per stop plus one minute per eight units purchased. Missing or stale prices receive internal comparison penalties. Only reported prices enter displayed costs. When starting fuel covers the trip and reserve, the search returns a direct plan. The dashboard values starting fuel at the median fresh quote along the route, with the filtered national median as fallback, and values subsequent consumption in purchase order. The estimated value of the fuel consumed and the cash spent at pumps are reported separately.

## Coverage and extension

The first provider covers Italy. France, Spain, Germany and an OpenStreetMap fallback are future providers. Brand filtering, fuel-specific weather and elevation effects, live traffic, station opening hours, ferry timetables and combined plug-in charging are outside this release. The routing service only verifies access according to its road graph. An external navigator can choose a different road or limit the number of imported via points. Each individual stop can also be opened for navigation.

To add a national provider, implement `FuelStationProvider` with a stable source ID and country set. Map its records into `FuelStation` and `FuelOffer`, use source-prefixed station IDs, and define time zone, grade, units, service, update cadence and attribution at the provider boundary. Register a cache and refresh policy per source in the catalog layer. Before combining providers, deduplicate only physically equivalent stations with compatible brands and coordinates, prefer national quotes, and leave unquoted stations unquoted. Introduce explicit currency handling before comparing offers from different currency regions. The corridor and optimizer consume normalized stations independently of CSV formats.

## Build and verification

Use JDK 17, Android SDK 36 and Gradle 8.11.1, as in the existing CI.

```sh
gradle :app:testDebugUnitTest :app:lintDebug :app:assembleDebug :wear:assembleDebug
gradle :app:assembleDebugAndroidTest
gradle :app:connectedDebugAndroidTest
adb install -r app/build/outputs/apk/debug/app-debug.apk
```

The final two commands require a compatible Android device or emulator. For the native map smoke test, run `gradle :app:connectedDebugAndroidTest -Pandroid.testInstrumentationRunnerArguments.class=no.lionflow.app.ui.screens.FuelMapRenderingTest` or dispatch the compile-check workflow on the feature branch to run all instrumentation tests. The map test queries rendered cluster and station features using a local MapLibre style and verifies recovery after removing a layer. Debug messages use the `FuelMap` and `FuelPlanner` tags. The debug build uses application ID `no.lionflow.app.debug`. For a manual pass, check the clustered map and mode filters in Italy, an itinerary with no stop, a trip needing several stops, a round trip with a via, and a reserve that makes the route infeasible. Change strategies, lock and replace stops, and verify that the station ETA, detour, fuel amount and cost recalculate. Repeat after switching vehicles and languages. Open the original charge planner with an electric car and confirm that its route and charging stops are available.

### Peugeot 208 follow-up verification

The previous layer setup stopped when it found the station source, even if some layers were missing. The device could also remain at the fallback camera if location arrived after map initialization. On an Android 11 emulator, two injected stations initially produced zero loaded source features even with the layers present. After separating price labels from markers and clusters, the same fixture rendered a two-station cluster at zoom 7 and restored the missing individual marker at zoom 15. The synthetic test runs with a local style. Live price labels and the behavior on the Peugeot owner's trip still need a device check. [Emulator verification](https://github.com/wi3ste/lionflow-mild/actions/runs/45364173024)

The feature workflow can reuse an Android debug keystore provided in the private GitHub Actions secret `FUEL_DEBUG_KEYSTORE_B64`. With no secret, Android Gradle Plugin uses a runner-generated debug certificate. Compare the old and new fingerprints before installing over a previous debug APK. If they differ, export a LionFlow backup before replacing the installation. Local builds can use the same existing local debug keystore.
